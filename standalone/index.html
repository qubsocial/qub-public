Phase 2 — tlock decrypt

drand quicknet round + signature + tlock ciphertext + plaintext fixture. BLS12-381 IBE via vendored tlock-js bundle (≈173 KB minified; tlock-js + drand-client + @noble/curves/hashes + chacha20poly1305 + buffer + sha3_256). The standalone never fetches drand from inside — it decrypts a ciphertext using a pre-supplied round signature, exactly the same path as the qub.social viewer.

Phase 3 — full pipeline

The same recovery code Phase 4 runs on a live qub, fed a pinned fixture instead of the network — one private (wrapped) and one public (bare) qub: resolve the delivery shape, check it agrees with the inner visibility, check the drand round binding, tlock-decrypt, verify body_hash, and recompute qub_id. The refuse: rows feed it inputs the protocol requires rejecting. The fixture is crates/qub-core/tests/vectors/standalone_pipeline_v1.json, which the Rust reference implementation also unlocks in its test suite.

Phase 4 — recover a real qub

Paste a qub link (from any host) or a bare Arweave transaction id. The page fetches the stored bytes from Arweave, fetches the drand round signature, and recovers the body. For a private qub the part after # is the AES-256-GCM key — the page never sends it anywhere, and browsers don't transmit fragments to servers. A public qub has no key.

What this is

        

          Reference implementation of qub's recovery path in vanilla JavaScript:
        

        

          Phase 1 verifies the OuterWrapper unwrap
          (AES-256-GCM with AAD bound to qub_id) via WebCrypto. Same
          byte-for-byte test vectors that the Rust crate and the TypeScript
          Worker compile against.
        

        

          Phase 2 verifies the inner tlock
          decrypt (BLS12-381 IBE over drand quicknet) by round-tripping a
          fixture: given a real drand round signature, the bundled tlock-js
          recovers the plaintext from a raw age-format ciphertext.
        

        

          Phase 3 runs the unlock procedure of
          PROTOCOL.md §8 end to end on
          pinned fixtures: delivery-shape resolution (§13.8), round binding
          (§4.3, §8 step 6a), tlock decrypt, body_hash, envelope/sealed
          equality, and qub_id recomputation (§4.1).
        

        

          Phase 4 runs that same code against the network: the
          stored bytes come from Arweave (multi-gateway fallback) and the round
          signature from drand (multi-endpoint fallback).
        

        

          Not covered here: ML-DSA-65 authorship signatures
          (§9) and transparency-log proofs (§16). For those, export the qub's
          .qub bundle and run the qub-verify CLI from
          this repository, which performs the full §11 third-party verification
          offline.
        

        

          The point: anyone can recover qub content without depending on
          qub.social. A third compliant implementation (alongside the Rust crate
          and the TypeScript Worker) round-trips every layer of the protocol.
